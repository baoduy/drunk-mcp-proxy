## Scope + Constraints

- All files under `src/drunk_ai_proxy/drunk_ai_proxy/`.
- Hard constraints from `AGENTS.md` and `.github/copilot-instructions.md`:
  - **One primary class per module**; no module-level business logic.
  - All module-level state in `self._attr`; no mutable module globals.
  - `from fastmcp.utilities import logging` + `logger = logging.get_logger(__name__)` at module level.
  - Pydantic v2 patterns; `X | Y` union syntax; lowercase generics.
  - Google-style docstrings on all public symbols.
- Compatibility: preserve all existing public import paths and test interfaces unless a task explicitly replaces them.
- Architecture guardrail: import-linter baseline must not gain new violations.
- All changes confirmed with `python -m pytest` (full suite) and `pyright` + `flake8 src tests` green.

## OOP Violation Inventory (P0)

### P0-1 · `app/middleware_provider.py`
- **Violation:** module-level business functions outside primary class.
- **Offending definitions:**
  - `_create_rate_limit_middleware` (line 151) — duplicates `MiddlewareProvider._create_rate_limit_middleware` (line 87).
  - `get_middlewares` (line 172) — orchestrates construction outside class.
- **Primary class:** `MiddlewareProvider` (line 37) — already exists.
- **Fix:** remove or collapse module-level wrappers; make `MiddlewareProvider.build()` the only callable path; any external caller that uses `get_middlewares()` is migrated to `MiddlewareProvider(cache).build()`.

### P0-2 · `utils/env_resolver.py`
- **Violation:** class API (`EnvResolver` line 20) shadowed by duplicate module-level functions.
- **Offending definitions:**
  - `resolve_env_var` (line 93)
  - `resolve_env_vars_in_dict` (line 118)
  - `resolve_env_vars_in_list` (line 133)
  - `resolve_env_vars` (line 148)
- **Primary class:** `EnvResolver`.
- **Fix:** remove module-level fallbacks; ensure all callers use `EnvResolver` static methods.

### P0-3 · `utils/config_yaml_uri.py`
- **Violation:** duplicate module-level wrappers around `ConfigYamlUriBuilder`.
- **Offending definitions:**
  - `build_skill_resource_uris` (line 165)
  - `build_prompt_resource_uri` (line 203)
- **Primary class:** `ConfigYamlUriBuilder` (line 25).
- **Fix:** remove module-level wrappers; update callers.

### P0-4 · `proxies/mcp/resource_path_utils.py`
- **Violation:** compatibility shim duplicates class method.
- **Offending definition:** `get_root_namespace` (line 34).
- **Primary class:** `ResourcePathNamespaceResolver` (line 8).
- **Fix:** remove module-level `get_root_namespace`; update callers.

### P0-5 · `utils/security.py`
- **Violation:** function-first implementation with late class wrappers creating a dual API surface.
- **Offending definitions:** `sanitize_error_response` (line 31), `validate_url` (line 148), plus alias class `SecurityUtils` (line 533).
- **Primary class:** `SecurityService` (line 515).
- **Fix:** promote class methods as definitive implementations; remove `SecurityUtils` alias class; expose stable re-exports from `utils/__init__.py` only.

### P0-6 · `utils/serialization.py`
- **Violation:** zero classes; business helper at module level.
- **Offending definition:** `to_dict` (line 8).
- **Recommended primary class:** `SerializationService`.
- **Fix:** move `to_dict` into `SerializationService` as a `@staticmethod`; update imports.

### P0-7 · `app/app_config_provider.py` (partial violation)
- **Violation:** two classes in one module (`AppConfigReader` line 21, `AppConfigProvider` line 44) violates one-primary-class rule.
- **Primary class:** `AppConfigProvider`.
- **Fix:** fold `AppConfigReader` into `AppConfigProvider` as a private mixin base or inline its methods; if keeping as an internal protocol, rename with leading underscore.

## Method SRP Inventory (P0.5)

### M1 · `LlmProxiesProvider._anthropic_messages_endpoint` (line 499)
- **Mixed concerns:** request parsing, payload validation, protocol conversion, provider dispatch, response formatting.
- **Proposed private helpers:**
  - `_parse_anthropic_request(request) -> dict[str, object]`
  - `_validate_anthropic_payload(body: dict[str, object]) -> None`
  - `_dispatch_anthropic_request(client, params: dict[str, object]) -> object`
  - `_build_anthropic_http_response(response, is_streaming: bool, model_id: str) -> Response`
- **Extraction order:** parse → validate → dispatch → format.
- **Acceptance criteria:** `_anthropic_messages_endpoint` body reduces to ≤ 10 lines of orchestration calls.

### M2 · `LlmProxiesProvider._get_models_by_provider` (line 167)
- **Mixed concerns:** cache lookup, remote I/O, DTO transformation.
- **Proposed private helpers:**
  - `_cached_model_key(provider_name: str) -> str`
  - `_fetch_provider_models_from_remote(provider_name: str) -> list[LlmModel]`
  - `_models_from_cache(key: str) -> list[LlmModel] | None`
- **Acceptance criteria:** cache policy lives only in one helper; remote I/O lives only in one helper.

### M3 · `MCPProxyServer.async_run` (line 191) and `_async_start_server` (line 108)
- **Mixed concerns:** startup telemetry, config load, provider construction, app composition, process serve.
- **Proposed private helpers:**
  - `_load_config_provider() -> AppConfigProvider`
  - `_configure_mcp_services(config: AppConfigProvider) -> McpBaseProvider`
  - `_configure_llm_services(config: AppConfigProvider) -> LlmProxiesProvider | None`
  - `_build_and_mount_app(mcp, llm) -> Starlette`
  - `_start_runtime_server(app: Starlette) -> None`
- **Acceptance criteria:** `async_run` is ≤ 15 lines of delegation calls.

### M4 · `McpBaseProvider._add_remote_{skill,agent,prompt}_proxy` (lines 313, 370, 402)
- **Mixed concerns:** overlap detection, runtime construction, provider creation, registration, error handling.
- **Proposed private helpers:**
  - `_warn_local_remote_overlap(resource_type: str) -> None`
  - `_build_remote_provider_runtime(entry) -> RemoteProviderRuntime`
  - `_register_remote_resource_provider(mcp, resource_type, provider) -> None`
- **Acceptance criteria:** each `_add_remote_*` method collapses to 5–8 lines; runtime creation is de-duplicated.

## Implementation Readiness

### Blockers / Open Questions
1. **`AppConfigReader` fold strategy** — confirm preference: inline methods into `AppConfigProvider` (cleaner) vs. rename to `_AppConfigReaderMixin` (keeps protocol legible).
2. **Compatibility window for module wrappers** — can wrappers be deleted immediately (faster) or must they emit `DeprecationWarning` for one release?

### Recommended First Phase
Start with **Phase 1.1** (utility module wrapper removal) — it is the highest-value, lowest-risk action: no behaviour changes, pure dead-code removal with call-site updates, and it unlocks all downstream refactors.
